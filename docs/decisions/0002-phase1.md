# ADR 0002 — Phase 1 decisions

**Status:** Accepted · **Date:** 2026-08-30 · **Phase:** 1 (PRD §7)

Records the design calls made building the Phase 1 "compile core loop": IR
validator, ~40 core commands, call-expressions, and proven dead-stripping.

## Call-expressions + command return types

Commands now carry a return type (`Signature { params, ret: Option<Ty> }`) and
may be used as values inside expressions (`let n: int = length(s)`), not just as
statements. Void commands (`ret: None`) remain statement-only; using one as a
value is a validator error. This is what makes a library of returning commands
(math/text/conversions) actually usable — the uniform call syntax (PRD §5.0) is
now uniform across statement and expression position.

## Types: added `int64` and `double`; byte-set deferred

Phase 1 slots are `int` (i32), `int64` (i64), `double` (f64), `text` (ptr).
**Byte-set (`SDT_BIN`) and the aggregate array/struct storage ABI are deferred
to Phase 2**, because they ride on the runtime↔library memory-ownership /
notification channel (`NRS_MALLOC`/`NRS_FREE_ARY`, PRD §1.2/D4), which is Phase-2
ABI work. Datetime is represented as `int64` Unix seconds (UTC) — no dedicated
date slot type yet.

## No implicit numeric conversion

Arithmetic operators require both operands to share one numeric type; mixing
(e.g. `double + int`) is a compile error, and conversion is explicit via
commands (`int_to_double`, …). This keeps the language footgun-free (PRD G9): no
silent widening/narrowing surprises. Integer literals are `int` when they fit in
32 bits, else `int64`.

## Command registry as the single source of truth

Command signatures + runtime symbols live in one `openepl_ir::registry`,
consumed by both the validator and the backend so they cannot disagree. In
Phase 2 this table is replaced by signatures loaded from the support-library ABI
(`openepl_get_lib_info`, PRD §5.4); the registry is the seam.

## Dead-strip: `-ffunction-sections`, refining D3's "one object per command"

PRD D3 calls for "one object per command" to get BlackMoon fragment extraction.
We instead group commands by family into a handful of `.c` files and compile
with **`-ffunction-sections -fdata-sections` + `-Wl,--gc-sections`**, which gives
per-*function* stripping regardless of file grouping — the same result with far
less file sprawl. Verified in CI (`unused_commands_are_dead_stripped`): a program
using only `print_int`/`print_text` links in neither `oe_sqrt` nor `oe_replace`
etc., and its `.text` is measurably smaller (M2).

## Runtime allocation & the leak caveat

Text-returning commands allocate results through `oe_alloc` (runtime owns
EPL-data memory, PRD D4). The spike does **not** reclaim them — no GC and no
notification channel yet — so allocations live for the process lifetime. This is
an explicit, documented Phase-1 limitation, resolved when the `NRS_*` channel
lands (Phase 2).

## Still deferred (unchanged from ADR 0001)

Designer / component model (Phase 3), support-library ABI headers (Phase 2),
binary IR encoding, second platforms (Phase 4), and IR node line-number tracking
for validator diagnostics (a Phase-1 follow-up: errors are message-only today).
