# ADR 0003 — Phase 2 decisions

**Status:** Accepted · **Date:** 2026-08-30 · **Phase:** 2 (PRD §7)

Records the design calls made adopting the real support-library ABI: the
slot calling convention, build-time introspection, the notification channel, and
the deliberate split that keeps dead-stripping intact.

## Scope: ABI half now; component/UI half gated on Q9

Phase 2 in the PRD has two halves — the support-library ABI + notification
channel (non-UI) and the component/event runtime on a portable UI layer. This
session delivered the **ABI half**; the component/UI half is **blocked on Q9**
(which portable UI toolkit underpins the designer + widgets), a product-level
decision deferred to the owner. Nothing here is wasted: UI components register
through the *same* `LibInfo` mechanism (EDK digest §9), so the component ABI is a
layer on top of what Phase 2 froze.

## Slot calling convention (PRD §11)

Commands are now invoked as `void cmd(Slot* ret, i32 argc, Slot* argv)` with
`%Slot = { i32, i32, i64 }` (16 bytes, value at offset 8) mirroring
`OpenEPL_Slot`. The backend marshals each argument into a stack `argv` array and
reads the return slot back. **Direct symbol calls** are kept (`call void
@oe_sqrt(...)`) — no dispatch table, no load-ordinal indirection (the EPL
mechanisms that made its binaries look like malware and resist debugging; G8).
The Phase-1 direct-typed-C signatures are gone; behavior is preserved
byte-for-byte (the `hello`/`demo` E2E outputs are unchanged, the guard on this
swap).

## Build-time introspection via dlopen; `LibInfo` is the source of truth

The compiler builds an introspection `.so` per library and `dlopen`s it to read
`openepl_get_lib_info` → `LibInfo`, populating the command `Registry`. This
retires `Registry::core()` as an authority: the C `LibInfo` is now the single
source of truth, and a unit test (`core_libinfo_matches_hardcoded_registry`)
asserts the in-memory table used by fast ir/backend unit tests never drifts from
it. `dlopen` uses `RTLD_LAZY` — introspection calls only the metadata function,
never the command impls (whose `oe_notify` symbol lives in core).

**Caveat:** `dlopen` runs a target-arch library in-process, so this native path
assumes host == target (x86_64-linux). Cross-compilation (Phase 4) needs a
sidecar manifest instead of `dlopen`.

## The dead-strip trap and its fix

`LibInfo` references every command, so if its table were linked into a program,
`--gc-sections` could strip nothing. The table therefore lives in a
metadata-only translation unit (`*_libinfo.c`) compiled into the introspection
`.so` **only**; command *implementations* are static-linked, the catalog is not.
This is EPL's `.fne` (design-time) vs `.fnr` (runtime) split and the G8
no-shipped-metadata story. The `unused_commands_are_dead_stripped` test guards it.

## Notification channel retires the leak

Text/array results allocate through `oe_notify(NRS_MALLOC, …)`; the runtime
tracks allocations and frees them in `E_DestroyRes`. Verified leak-clean under
AddressSanitizer. The per-library dynamic-load init/notify vtable
(`BlackMoonInitAllElib` analog) is specified but deferred — static-linked spike
libraries reach the runtime through the global `oe_notify` symbol.

## Deferred to Phase 3+

Byte-set (`SDT_BIN`) + `NRS_FREE_ARY`; the file/text libraries as separate
support libraries; user subroutines / control flow; the UI-component interface
contract and the portable UI layer (gated on Q9); the dynamic-load vtable; the
cross-compilation sidecar manifest.
